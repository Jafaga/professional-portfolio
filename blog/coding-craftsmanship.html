Coding Standards Aren’t Just Curly Braces

How the rules that once felt irritating helped me become a clearer teammate, writer, and computer science student.

Justine AfagaComputer Science graduate student · Hawaiʻi
Published Sep 25, 2024Revised Aug 14, 20268 minute read
coding-craftsmanship.logPERSONAL_NOTE

At first, coding standards felt like one more list of errors standing between me and a finished assignment. I would get the program working, feel ready to move on, and then the linter would point out my spacing, naming, or curly braces. Honestly, it could be irritating. But as my assignments became larger—and especially when I started sharing code with a team—I realized those “picky” rules were doing more than making my work look nice.

WHAT YOU’LL TAKE AWAY

Coding standards can help you learn a new language, make teamwork less confusing, and turn your code into something another person can actually continue.

The small details started to matter

Things like clear names, consistent formatting, and useful comments may seem small while I am writing code. They matter much more when I return to the same file later and have to remember what I was thinking. They matter even more when someone else opens that file for the first time.

For me, code is a lot like writing. If I want another person to understand my point, I have to organize my thoughts. A program can run correctly and still be hard to read, just like an essay can have good ideas but lose the reader if everything is scattered.

Good code is not only code that works. It is code that communicates what it is trying to do.

TypeScript showed me that standards can teach

I did not expect coding standards to help me learn a language. I thought they were rules you followed after you already understood everything. When I began learning TypeScript, my Java background helped because classes, interfaces, and static types felt familiar. Still, TypeScript had its own way of organizing those ideas.

Following its conventions gave me a framework—almost like a cheat sheet—for how the language was meant to be used. Over time, I was not only learning how to make TypeScript run. I was learning how to write TypeScript in a way that was easier to maintain and easier for someone else to recognize.

Teamwork makes messy code obvious

When everyone on a team writes code in a completely different style, bringing the pieces together can become a nightmare. Even good logic takes longer to understand because each file feels like it came from a different project.

In my group work, shared standards saved time. Instead of arguing about tabs, spaces, or braces, we could focus on whether the feature actually worked. When the formatting stayed consistent, it was easier to review someone else’s logic, find problems, and make changes without guessing.

What I practice now

A SIMPLE CHECKLIST
  1. Name things for the next reader.I try to choose names that explain the purpose instead of forcing someone to decode an abbreviation.
  2. Let tools catch the small issues.Linters can feel strict, but fixing warnings early keeps small habits from becoming a bigger cleanup later.
  3. Comment the reason, not every line.A useful comment explains a decision or unusual behavior rather than repeating what the code already says.
  4. Follow the team’s shared style.Consistency across the project matters more than proving that my personal preference is the best one.
  5. Read my own code as if it belongs to someone else.If I cannot follow it after a short break, it probably needs to be clearer.

Growing as a writer helped me grow as a developer

Revising this reflection also made me notice how similar writing and programming really are. My older writing sometimes repeated the same idea because I wanted to make sure the reader understood me. Now I am learning to trust a stronger structure: introduce the point, give a real example, explain what changed, and then move forward.

I want to bring that same growth into my code. I do not need every program to look clever or every paragraph to sound perfect. I want both to be clear, intentional, and honest about what I am still learning.
